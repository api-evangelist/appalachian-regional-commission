# Appalachian Regional Commission

> The Appalachian Regional Commission (ARC) is a federal-state partnership investing in the economic
> future of Appalachia — 423 counties across 13 states. ARC publishes no developer program and no
> API documentation, but it operates two live, anonymous, machine-readable surfaces: the WordPress
> REST API behind www.arc.gov, and 108 public hosted feature services in its own ArcGIS Online
> organization. Both need no key and no signup.

Generated by API Evangelist on 2026-09-07 from artifacts in this repository. ARC does not publish an
llms.txt of its own (https://www.arc.gov/llms.txt returns 404). Everything below was verified live on
that date.

## What is actually callable

- [ARC WordPress REST route index](https://www.arc.gov/wp-json/): the self-describing contract — 371
  routes, 16 namespaces, full argument schemas. Start here.
- [ARC ArcGIS services directory](https://services.arcgis.com/nkunl3y8FDxPkXDl/arcgis/rest/services?f=json):
  108 public feature services. Always send `f=json` or `f=geojson`; omitting `f` returns HTML.

## Geospatial and statistical data (services.arcgis.com/nkunl3y8FDxPkXDl/arcgis/rest)

This is where ARC's numbers live. Query with
`/services/{service}/FeatureServer/0/query?where=1%3D1&outFields=*&f=geojson`.

- `arc_counties` — the 423 counties of the Appalachian Region, keyed on FIPS
- `arc_boundary` — the ARC region boundary
- `arc_local_development_districts` — the 74 LDD boundaries
- `arc_county_economic_status_fy2027_tiger` and `arcfy2014`…`arcfy2025` — annual county economic-status designations
- `arc_distressed_areas_fy2027_tiger` — distressed areas
- `arc_acs_2019_*` … `arc_acs_2023_*` — ACS poverty rates, median household income, SNAP, broadband, education attainment, population change
- `arc_rural_urban_county_types`, `arc_congressional_districts_119th`, `arc_subregion_counties`

## Conventions an agent needs

- Both surfaces are READ ONLY for anonymous callers. There is no write, no purchase, no send — and
  therefore nothing to undo. `/wp/v2/report` answers OPTIONS with `Allow: GET`; every feature service
  advertises `capabilities: Query` only.
- WordPress paging: `page` + `per_page` (max 100), with `X-WP-Total`, `X-WP-TotalPages` and an RFC 5988
  `Link` header.
- ArcGIS paging: `resultOffset` + `resultRecordCount` (max 1000), with `properties.exceededTransferLimit`.
- No rate limits are published and no rate-limit headers are returned on either surface.
- Errors differ: WordPress returns a truthful HTTP status with `{code, message, data.status}`; ArcGIS
  returns **HTTP 200** with `{error:{code, message, details}}`. Do not branch on `response.ok` for ArcGIS.
- Caching: WordPress `max-age=86400` and no ETag; ArcGIS `max-age=30` with an ETag.

## What ARC does not publish

- No OpenAPI, no developer portal, no API documentation, no changelog, no status page, no SLA
- No `/data.json` federal open-data inventory, and no data.gov organization
- No OGC API - Features or WFS on any of the 108 services (probed; `/OGCFeatureServer` and
  `/WFSServer` both miss)
- No `security.txt`, no agent card, no MCP server, no SDKs, no GitHub organization
- data.arc.gov (the ARC Data Report Tool) sits behind a Cloudflare managed challenge and returns 403
  to every non-browser client
